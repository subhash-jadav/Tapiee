How Tapiee works

Tapiee turns YouTube songs into a cassette you design (cover, stickers, photos, a note inside the case) and share with one link. This page explains every flow, from tapping “Start your mixtape” to a friend pressing play.

01The big picture

Five places do the work. The browser is the studio; Vercel runs the pages and API; Neon keeps tapes; Blob keeps photos; YouTube and iTunes supply song data.

There are no accounts. Ownership of a tape is a secret edit key that only the creator's browser knows. The server stores just a hash of it.

03The whole journey, A → Z

  1. Open the site. Vercel's proxy.ts adds security headers; the home page loads. Your theme and sound choice come from localStorage.
  2. Start your mixtape → /create. Search YouTube or paste video/playlist links. Every song you pick goes into “Your tape”, saved in tapie:collect, so a reload loses nothing.
  3. Start designing. The editor opens with the picked songs and shows “reading your songs…”.
  4. Vibe engine runs once. Thumbnail colours (browser) + genre/year/tags (/api/vibe) → a mood → a matching cassette style and a short note inside the case.
  5. You design. Change colours, fonts, cover photo, stickers, polaroids, the note. Every change is kept as a draft in mixtape:draft.
  6. Save & get link. POST /api/cassettes: checked, rate-limited, photos uploaded to Blob, tape saved in Neon. You get an id and a secret edit key.
  7. The browser remembers it. {id, key, title} is added to mixtape:mine and the address becomes /edit/id#key.
  8. Share. You send /c/id (never the edit link). Native share sheet on phones; copy / WhatsApp elsewhere.
  9. Your friend opens it. The server reads the tape from Neon and renders it; photos stream from the Blob CDN; songs play through the YouTube player.
  10. Later edits / delete. From “My tapes” or the edit link: PUT / DELETE with the key. Removed photos are deleted from Blob too.

04Picking songs

Song search and link import run on the server, which looks the songs up on YouTube and returns clean titles to the browser.

Title clean-up. splitTitle() turns “Artist - Song (Official Video)” into a clean title + artist.
What's refused. Private/empty playlists, auto-generated “RD…” mixes, non-YouTube links, more than 100 tracks per tape.

05Vibe engine (auto design)

Runs once, when you press Start designing. Never restyles your tape later on its own.

06Saving a tape

The edit key is sent back once. The database only keeps its SHA-256 hash, so even someone who reads the database can't edit tapes.

12Where everything lives

BROWSER

Temporary & personal

Edit keys, My tapes, drafts, picked songs, theme, sound. Lives in localStorage and React state in memory while the page is open.
NEON

The tapes

One row per tape (JSON) + rate-limit counters. ~2 KB per tape. Database sleeps when idle.
BLOB

The photos

One file per photo, served from Vercel's CDN worldwide. Deleted with its tape.
VERCEL

Nothing permanent

Functions start, answer, and stop. Only short-lived memory (DB client, photo uploads in progress).
YOUTUBE

The music

Audio and thumbnails are never copied: always streamed from YouTube.
ITUNES

Song facts

Genre and year, looked up only while the vibe is worked out. Nothing stored.

Current usage (Nov 2026)

Neon database: 7.9 MB of 1 GB (7.5 MB is Postgres's own base; tapes only 15 KB)
Blob photos: a few MB of 1 GB. Check Vercel → Storage → tapie-public.

13Security

Edit keys. 24 random characters; stored only as a SHA-256 hash; compared in constant time. Shared links (/c/) never contain them.
Validation. Every tape is checked with Zod: types, lengths, colours, fonts, image format, counts. Bad data → 400.
Size guard. Bodies over 4.4 MB are refused while still arriving (413), under Vercel's 4.5 MB cap.
Content-Security-Policy (proxy.ts). Scripts only from the site with a nonce; images only from the site, YouTube thumbnails and Blob; frames only YouTube.
Rate limits per IP, shared through Neon so all Vercel copies agree. The IP is read from Vercel's own header, not trusted blindly.
Secrets. Database URL lives in Vercel env vars; Blob uses OIDC login. Nothing secret is in the code or GitHub.

Locally (npm run dev) with no DATABASE_URL, tapes are JSON files in data/cassettes/ and photos stay inside the tape. Same code, no cloud needed.
